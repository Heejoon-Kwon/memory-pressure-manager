# memory-pressure-manager

Ubuntu GNOME용 메모리 압박 모니터 및 자동 대응 도구입니다. 앱·프로세스·Chrome 탭의 우선순위를 관리하고, 페이지 회수와 브라우저 정리, 프로세스 종료 결과를 측정해 유효한 대응 규칙을 재사용합니다.

## 기능

- 가용 메모리, PSI, 스왑 상태 감시 및 상단 바 표시
- 앱·프로세스·Chrome 탭별 보호와 숫자 우선순위
- 권한이 있는 전용 cgroup의 페이지 회수
- Chrome 비활성 탭 회수와 백그라운드 웹 앱 종료
- OpenAI 기반 사전 계획, 로컬 근거 문서 검색, 검증된 대응 규칙 저장
- 월간 API 예산 제한과 로컬 비용 기록
- 압축 스왑 상태 확인 및 zram 설치 도구

시스템 권한과 Chrome API에서 제공하는 정보에 따라 사용 가능한 기능이 달라집니다. 커널 OOM이나 앱 자체 오류를 완전히 방지하지는 못합니다.

## 설치

Ubuntu GNOME 세션과 Python 3, venv, GTK 3용 PyGObject가 필요합니다.

```sh
git clone https://github.com/Heejoon-Kwon/memory-pressure-manager.git
cd memory-pressure-manager
./install.sh
```

설치 프로그램은 Python 가상환경, 사용자 서비스, GNOME 확장을 구성하고 서비스를 시작합니다. `config.yml`이 없으면 `config.example.yml`을 복사해 생성합니다. 설정 파일은 소유자만 읽을 수 있도록 보관하세요.

상단 바가 나타나지 않으면 GNOME 세션의 터미널에서 다음 명령을 실행합니다.

```sh
./panel.sh
```

GNOME Shell이 새 확장을 아직 인식하지 못한 경우에는 다음 로그인에서 활성화됩니다. 관리창은 별도로 실행할 수 있습니다.

```sh
/usr/bin/python3 window.py
```

## 우선순위

| 설정 | 동작 |
|---|---|
| 보호 | 자동 종료·탭 회수 대상에서 제외 |
| 1~999 | 숫자가 클수록 먼저 정리. 중복 값 허용 |

일반 사용자 앱·프로세스와 Chrome 탭의 기본 우선순위는 500입니다. 보호는 사용자가 직접 지정합니다. 시스템·세션·다른 사용자 프로세스는 조회 전용입니다. 미식별 JVM, 대표 프로세스가 모호한 대상, 보호된 앱을 자식으로 둔 프로세스는 자동 종료하지 않습니다.

보호되지 않은 프로세스는 종료될 수 있으며 저장하지 않은 작업을 잃을 수 있습니다. 종료 요청에 응답하지 않으면 기본 8초 후 보호와 프로세스 식별 정보를 재확인하고 강제 종료로 전환합니다. `watch.allow_force_kill`로 이를 끌 수 있습니다.

관리창에서 대상을 검색하고 보호와 우선순위를 설정합니다. 아이콘이 있는 항목을 먼저 표시하며, 앱은 각 그룹 안에서 메모리 사용량순으로 정렬합니다. 화면 정렬과 자동 대응 우선순위는 별개입니다. 앱별 RSS에는 공유 메모리가 중복될 수 있으므로 호스트 전체 사용량에 합산하지 않습니다.

## OpenAI 설정

`config.yml`에서 다음 값을 설정합니다.

| 항목 | 의미 |
|---|---|
| `openai.automatic_analysis` | 자동 AI 분석 활성화. 기본값 `false` |
| `openai.api_key` | OpenAI API 키. `OPENAI_API_KEY` 환경변수도 지원 |
| `openai.model` | 모델 ID. 기본값 `gpt-6-luna` |
| `openai.monthly_budget_usd` | 로컬 월간 예산. 기본값 0은 API 호출 비활성화 |

모델은 계정에서 사용 가능하고 가격 조회가 가능해야 합니다. 설정 후 서비스를 재시작합니다.

```sh
systemctl --user restart memory-pressure-manager.service
```

자동 AI 분석은 실험 기능이며 명시적으로 켠 경우에만 실행합니다. 활성화하면 AI에 메모리 지표와 허용된 행동 후보, 관련 근거 문서를 전달합니다. 출력은 허용된 행동 ID로 제한하며 실제 실행 전에 로컬 정책을 다시 검사합니다. 예산·가격·연결 문제로 AI를 사용할 수 없으면 허용 범위의 로컬 규칙으로 대응합니다. 로컬 비용 추정치는 실제 청구액과 다를 수 있습니다.

다음 명령은 소액의 실제 API 요청을 보내 연결을 검사합니다. 앱은 종료하지 않습니다.

```sh
.venv/bin/python memory_pressure_manager.py --config config.yml --check-ai
```

## Chrome 연결

1. `chrome://extensions`에서 개발자 모드를 켭니다.
2. **압축해제된 확장 프로그램을 로드합니다**에서 `chrome-extension` 폴더를 선택합니다.
3. 확장 ID를 복사해 프로젝트 폴더에서 등록합니다.

```sh
./install-chrome-host.py <extension-id>
```

관리창 또는 확장 팝업에서 탭별 우선순위를 설정합니다. 여러 프로필에서 사용할 경우 각 프로필에 확장을 설치하고 동일한 확장 ID를 사용해야 합니다. 등록 명령은 한 개의 ID를 허용합니다.

일반 비활성 탭은 메모리에서 내리고, 다시 선택하면 페이지를 로드합니다. 백그라운드 웹 앱은 해당 앱 페이지를 닫습니다. 활성·고정·소리 재생·시크릿·보호 탭은 제외합니다. Chrome API로 표시 모드나 창을 확인하지 못하면 자동 제어하지 않습니다.

탭 설정은 현재 Chrome 세션과 주소에 적용됩니다. 브라우저 재시작·확장 재로드·주소 변경 후 기본 우선순위로 돌아갑니다. 회수나 종료로 저장하지 않은 입력이 사라질 수 있습니다.

확장은 HTTP(S) 페이지의 표시 모드를 확인하는 권한을 사용합니다. 페이지 본문·입력 내용·쿠키는 읽지 않습니다. 탭 주소는 Chrome 내부에 두고, 제목과 파비콘은 로컬 관리창 표시용으로만 공유합니다. 이 정보는 OpenAI에 보내지 않습니다.

## 대응 정책과 스킬

기본 대응 순서는 페이지 회수, 브라우저 회수, 앱 종료입니다. 실시간 경로는 네트워크 호출과 분리됩니다. 페이지 회수는 위임된 cgroup 쓰기 권한이 있을 때만 실행합니다. 긴급 상황에서는 API를 기다리지 않고 로컬 정책으로 대응합니다.

개별 앱·웹 앱 종료는 효과 이력과 통계에 저장하며 자동 재실행 규칙으로 사용하지 않습니다. 페이지·비활성 탭 회수는 완료와 관측된 개선을 확인하면 로컬 회수 규칙으로 보관합니다. 회수에는 현재 조건에서 유효한 로컬 규칙을 먼저 사용하고, 재사용 후 효과가 확인되지 않으면 해제합니다. 이 평가는 관측된 개선이며 다른 프로세스의 영향까지 완전히 분리하지는 못합니다.

관리창의 **대응 기록 보기**에서 AI 요청·제안, 행동 결과, 로컬 회수 규칙을 확인할 수 있습니다. 로컬 이력은 최대 2,000건을 보관하며 화면에는 최근 200건을 표시합니다.

압축 스왑 설치와 상세 정책은 [메모리 관리 정책](docs/MEMORY_POLICY.md)을 참고하세요.

## 운영 및 진단

```sh
systemctl --user status memory-pressure-manager.service
journalctl --user -u memory-pressure-manager.service -n 30
.venv/bin/python memory_pressure_manager.py --config config.yml --diagnose
```

진단 출력에는 설치·실행 빌드, 실행 경로, Chrome 연결 상태, 기능 권한과 후보 제외 이유가 포함됩니다. API 키 값은 출력하지 않습니다.

```sh
# 서비스 중지
systemctl --user stop memory-pressure-manager.service

# 로그인 시 자동 시작 해제
systemctl --user disable --now memory-pressure-manager.service
```

## 예방 대응과 커널 보호

기본 예방 구간은 가용 메모리 25%에서 주의, 20%에서 종료 없는 회수, 27%에서 대응 해제입니다. 메모리가 빠르게 감소하면 30초 예측 구간으로 페이지·비활성 탭 회수를 앞당깁니다. 이 예방 구간에서는 앱과 Chrome 앱 창을 종료하지 않습니다. 앱 종료는 별도 압박 확인 조건과 가용 메모리 8% 이하 조건을 함께 만족해야 하며, 새 앱과 새 셸이 있는 터미널에는 60초 유예를 둡니다. `prevention` 설정으로 조절하며, 실시간 대응은 API를 기다리지 않습니다. 자동 AI 분석을 명시적으로 켠 경우에만 OpenAI가 압박 해소 후 최근 성공·실패 기록과 근거 문서를 분석합니다. 이 분석의 성능 향상 효과는 검증되지 않았습니다. 검증된 스킬과 누적 결과는 로컬 대응 선택에 재사용합니다.

앱의 보호 설정을 커널 OOM 선택에도 적용하려면 관리자 헬퍼를 설치합니다.

```sh
sudo .venv/bin/python install_kernel_guard.py
```

헬퍼는 root 소유 경로에 설치되며 지정된 사용자 프로세스의 UID·시작 시각을 재검사한 뒤 `oom_score_adj=-1000`을 적용합니다. 보호 앱의 자식 프로세스와 모니터도 포함합니다. root 소유의 전용 앱 cgroup에 한해 systemd-oomd 제외 속성도 적용하고, 관리창에 각각의 실제 적용 수를 표시합니다. 사용자 소유·혼합 cgroup 등 OOM 데몬 정책이 신뢰하지 않는 범위는 보호됐다고 표시하지 않습니다. 보호 해제나 서비스 종료 시 적용 전 값을 복원합니다. 이 기능도 메모리 할당 실패, 사용자 명령, 앱 오류까지 막지는 않습니다.

관리자 서비스는 `memory-pressure-guard-<UID>.service`입니다. 제거할 때는 해당 서비스를 중지·비활성화한 뒤 `/etc/systemd/system`의 서비스 파일과 `/usr/local/lib/memory-pressure-manager/kernel_guard.py`를 삭제하고 `systemctl daemon-reload`를 실행합니다. 압축 스왑은 별도의 `configure_memory.py`로 구성합니다.
