# 메모리 자동 관리 정책과 근거

## 조사한 구현과 적용 범위

- [Meta TMO](https://engineering.fb.com/2022/06/20/data-infrastructure/transparent-memory-offloading-more-memory-at-a-fraction-of-the-cost-and-power/): 압박 피드백을 이용해 메모리를 압축 RAM/SSD로 오프로딩합니다. 여기서는 원본 TMO를 이식했다고 주장하지 않습니다. 회수 대상을 제한하고, 압박이 심하면 선제 회수를 중단하는 원칙을 적용합니다.
- [cgroup v2 memory.reclaim](https://docs.kernel.org/admin-guide/cgroup-v2.html): 특정 cgroup의 페이지 회수 인터페이스입니다. 위임된 쓰기 권한이 있는 사용자 전용 앱 범위만 사용합니다. 권한이 없으면 실행하지 않고 관리창에 이유를 표시합니다.
- [zram](https://docs.kernel.org/admin-guide/blockdev/zram.html) 및 [zswap](https://docs.kernel.org/admin-guide/mm/zswap.html): 압축은 CPU 비용을 사용해 물리 메모리/디스크 I/O를 절약할 수 있습니다. 압축률과 워크로드에 따라 효과가 다르고 전체 메모리 부족을 없애지는 않습니다.
- [systemd zram-generator](https://github.com/systemd/zram-generator): 영구적인 압축 스왑 구성에 사용합니다. Ubuntu 26.04의 패키지는 `systemd-zram-generator`입니다. 기존 압축 설정은 덮어쓰지 않습니다.

## 실행 순서

1. 가용 메모리와 PSI를 확인합니다. 단순히 스왑이 많이 찼다는 이유로 프로세스를 종료하지 않습니다.
2. 주의 단계에서 권한과 상태가 허용되면, 보호하지 않은 전용 앱 범위의 페이지를 기본 64 MiB씩 회수합니다. 호출은 작업 스레드에서 수행합니다. 압축 스왑 여유가 있으면 익명 페이지 회수도 허용하며, 그렇지 않으면 파일 페이지 회수만 요청합니다. 보호 범위·혼합 범위·시스템 서비스는 제외합니다.
3. 회수 전략은 저장된 규칙을 먼저 사용합니다. 없으면 관련 근거 문서만 검색해 AI 요청에 함께 넣습니다. AI는 허용된 행동 ID만 선택하며 명령어나 커널 설정을 생성하지 않습니다.
4. 실제 회수 요청이 완료된 뒤 가용 메모리 증가와 PSI를 관찰합니다. 개선이 확인된 경우에만 규칙을 저장합니다. 이는 관측된 효과이며 인과관계를 완벽히 증명하지는 않습니다. 효과가 없으면 규칙을 제거합니다.
5. 페이지 회수가 불가능하거나 부족하면 브라우저 회수, 앱 종료 순서로 진행합니다. 보호된 대상은 항상 로컬 정책으로 다시 검사합니다. 긴급 상황은 API를 기다리지 않습니다.

## 압축 스왑 설치

일반 사용자 프로세스가 커널 압축 스왑 장치를 만들 권한은 없습니다. 아래 확인 명령은 변경하지 않고 현재 상태와 적용할 설정만 출력합니다.

```sh
.venv/bin/python configure_memory.py --config config.yml
```

새 zram 구성이 가능하다고 표시된 환경에서 다음 명령으로 설치할 수 있습니다.

```sh
sudo .venv/bin/python configure_memory.py --config config.yml --apply
```

RAM의 50%, 최대 8 GiB의 논리 zram 장치를 기본값으로 생성하고 우선순위 100으로 스왑에 추가합니다. 실제 RAM 소모는 압축된 페이지와 메타데이터입니다. 기존 디스크 스왑은 유지하며 `swapoff`하지 않습니다. 기존 디스크 스왑의 데이터가 즉시 zram으로 이동하는 것은 아닙니다. zswap 또는 다른 zram 관리자가 있으면 자동으로 중복 설치하지 않습니다.

설치된 설정은 `/etc/systemd/zram-generator.conf.d/60-memory-pressure-manager.conf`입니다. 되돌리려면 이 파일을 삭제하고 작업을 저장한 뒤 재부팅하세요. 메모리가 부족할 때 스왑 장치를 즉시 끄는 작업은 하지 마세요.

## 스킬의 의미와 관측

스킬은 임의의 셸 스크립트가 아니라 검증된 행동·조건의 규칙입니다. 다른 앱의 동시 메모리 사용 때문에 유효한 작은 개선을 버리지 않도록, 최소 약 32 MiB 개선과 행동 완료 여부를 확인하며 시스템 전체가 정상으로 돌아왔는지는 별도 판단합니다. 정책 변경으로 종료가 차단된 경우는 효과 검증 실패와 구분합니다. 미식별 JVM과 세션 보조 프로세스는 자동 종료하지 않습니다.

RAG는 로컬 문서 검색이며 별도 LLM이나 벡터 DB를 상주시켜 RAM을 더 사용하지 않습니다. API 비용 가드는 기존과 동일하게 적용됩니다. 관리자 권한이 필요한 커널 기능이 아직 설정되지 않은 환경에서 마치 실행된 것처럼 스킬을 만들지 않습니다.
